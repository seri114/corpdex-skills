# corpdex クロールタスク

クロールタスクを1件実行して、企業サイトの調査結果を提出変更(changes)に組み立てる。
あなたが行うのは **①タスクの取得 ②公式サイトの検索 ③`corpdex fetch` の結果を読む ④changes の組み立て ⑤提出** の5つだけ。

**絶対守則(理由は各節)**

1. **ページの取得は `corpdex fetch` のみ**。WebFetch・ブラウザ・curl など CLI 以外の取得をしない(クロールマナー: robots.txt・同一ドメイン3秒間隔・1タスク上限30 fetch は CLI がコードで強制する — ADR 0011。CLI を迂回するとマナーの保証が消える)。
2. **出典に書いてあることだけを提案する**。要約・意訳・類推・別ページからの持ち込みをしない。提出物はレビューで出典URLを再取得して突合される(値が出土しないchangesは棄却される)。
3. **取り込み管理フィールドは原則1つも提案しない**: `name` / `name_reading` / `links.website` / `contact.postal_address` / `basics.founded_on` / `basics.representative` / `basics.employees` / `gbizinfo_industries`(gBizInfoが常に正 — ADR 0009)、`basics.market`(上場市場はEDINET×東証data_jの権威ソース取り込みが全社確定する — #153)。会社概要テーブルやIRページに載っていても changes に入れない(入れると機械検証で提出ごと拒否される)。**例外は資本金(`basics.capital_jpy`)のみ**: タスクJSONの `supplemental_fields` に含まれているときだけ、会社概要の資本金を提案してよい(後述 — ADR 0009の例外。リストにないときは資本金も提案しない)。


## 0. 前提

- `corpdex` CLI が入っている(未導入なら `${CORPDEX_API_URL}` の配布ページ `/dist` にログインした状態で tarball をダウンロードし、`npm i -g <ダウンロードしたファイル>`)
- 環境変数 `CORPDEX_TOKEN`(tasks スコープ以上のPAT)と `CORPDEX_API_URL` が設定済み
- **1タスクにつき空の作業ディレクトリで実行する**(fetch計数などの状態を `.corpdex/` に置くため)

両方の環境変数がないと claim が導線表示で止まる。ユーザーに設定を促してから再開すること。

## 1. タスクの取得

```
corpdex task claim
```

- タスクJSON(`task: null` なら配布できるタスクなしで終了)。読むべきもの:
  - `company_name` / `corporate_number` — 調査対象の企業(1タスク=1企業)
  - `priority_fields` — 未調査フィールド(優先して探す)
  - `supplemental_fields` — 条件付き補充フィールド(このリストに `basics.capital_jpy` があるときだけ資本金を提案してよい — 空配列なら資本金は提案しない。リストの内容はサーバーがマスター状態から判定するため、自分で判断しない)
  - `master` — 各フィールドの現在値(全置換の基準。`{status:"unresearched"}` は未調査)
- スキーマバージョン不一致で停止を促されたら、ユーザーに CLI の更新を依頼して終了(クロールを始めない)。

## 2. 公式サイトの検索

環境の WebSearch で `<company_name> 公式サイト` を検索する(同名企業・グループ会社が多い場合は `<company_name> 法人番号` や `<company_name> <事業種> <地域>` を併用)。

**社名・ドメインが一致して見える候補でも別法人(同名他社)・ドメイン再利用・移転済みの実例が多数ある — 検索1位で社名とドメインが完全一致でも信用しない。公式サイトの確定は、すべてのタスクで住所照合によって行う**(#152):

1. `corpdex fetch "https://info.gbiz.go.jp/hojin/ichiran?hojinBango=<法人番号>"` で gBizInfo 法人個別ページを開き、**住所**(と代表者名)を控える(社名+法人番号で直接アクセスできる。HTMLなので fetch で読める)
2. 候補サイトのトップ→会社概要を取得し、**所在地を gBizInfo の住所と照合する**
3. **所在地が一致する候補だけ**を公式サイトとして採用する

住所照合の規則:

- 比較は**都道府県〜市区町村〜町名〜番地**で行う。郵便番号・ビル名・階・「1丁目2番8号/1-2-8」の表記ゆれは無視する
- **代表者名は補助材料**: 一致すれば確定材料になるが、代表変更・商号変更で gBizInfo が旧情報のままの実例があるため、**代表者名の不一致だけでは候補を外さない**(住所で判断する)
- 候補の正式社名が対象企業の**旧社名**でも、住所照合で同一法人なら採用してよい(商号変更)。ただし「〇〇ホールディングス」など親会社・子会社の別法人は、住所が同じ建物でも採用しない
- 候補の会社概要に**法人番号の明示**があれば、番号一致で確定してよい(住所照合に代わる)
- 住所が一致しない・読み取れない候補(画像化・パーキングページ等)は使わない。ドメインや社名の見た目は判断材料にしない

検索結果の候補の選び方(この条件を満たす候補を住所照合にかける):

- ドメインまたはサイト内表記が対象企業と一致(英名・略称・旧社名も可)
- 検索個人ブログ・SNS・ポータルの企業ページは公式サイトではない

**検索で候補が出ない・検索手段が使えないときは、発見経路を変える**(対象企業のサイトを直接探しても出ない企業が、別の主体を経由すると見つかる — #293)。いずれの経路で見つけた候補も、採用は通常どおり住所照合で行う:

- **親会社・グループ公式サイトのグループ企業一覧**: 社名にグループ名を含む等で親会社・グループが推定できるとき、その公式サイトの「グループ企業一覧」「グループ紹介」ページから対象企業の候補サイトを辿る
- **Wikipedia 記事の外部リンク**: `<company_name> Wikipedia` 等で記事を探し、記事の外部リンクから公式サイト候補を拾う。検索手段が使えないときは `https://ja.wikipedia.org/wiki/<company_name>` の直接 fetch でもよい(記事名は裸の社名であることが多い)

代替経路でのページ取得(グループサイト・Wikipedia を含む)もすべて `corpdex fetch` で行い、fetch計数に加算される(絶対守則1の適用対象)。経路を辿る分だけ fetch は増える(§3 の「通常4〜7回」を超える)ため、1タスク上限30に余裕を持たせる。

コストは gBizInfoページの fetch +1(会社概要は取材で必ず取得するページなので追加ではない)。住所照合を通る候補が1つもない・gBizInfoページ自体が取得できない場合は、**公式サイトを特定できない**とする。**特定できない場合は提出しない** — `corpdex task abort --reason site_unidentifiable` でリースを放棄し、ユーザーに報告して終了する(出典のない提案はできない)。

## 3. 取材(`corpdex fetch`)

```
corpdex fetch <URL>          # 整形済みテキスト(既定)
corpdex fetch <URL> --raw    # HTML原文(整形で情報が失われたときの逃し道。計数は共通)
```

**回す順序**(目安。1タスクのfetchは通常4〜7回(gBizInfoページの住所照合+1を含む)、CLIが30回で打ち切る):

1. トップページ → 2. 会社概要・会社情報・プロフィール(§2の住所照合はここで確認) → 3. お問い合わせ → 4. 必要なら事業内容・製品・採用
2. 上場市場(basics.market)はクロール対象外(#153 — EDINET×東証data_jの権威ソース取り込みが全社確定するため、サイトに上場表記があっても読む必要はない)
3. 途中で新情報が出なくなったら打ち切ってよい(部分提出は正当な提出方法)

**線形化テキストの読み方**(既定の出力):

- 1行目 `# タイトル`、2行目に meta description が続く
- 見出しは `##` レベル、リストは `-` 項目、テーブルは `セル | セル` の行
- リンクは `リンクテキスト <絶対URL>` — ページを辿るリンクはここから拾う。グローバルナビ・フッター・本文のリンクがすべてここに出る(ヘッダーとフッターで同じリンクが重複して出るのは普通)
- **ナビ・フッターのリンク列挙が本文より長いサイト(大企業に多い)は、列挙を読み込まず本文の見出しから読む**。辿るリンクだけ拾う
- **テーブルの行が崩れて見えるとき**(ラベルと値が別行・セルの折り返しで語が分断)は `--raw` で元の構造を確認してから転記する
- ページによっては整形で表記が失われる。テーブルや定義リストの読み取りに違和感があれば `--raw` で確認する

**サイト内リンクが拾えないとき(JS描出・navと実URLの不一致)は sitemap.xml を読む**:

- `corpdex fetch <サイトのルートURL>/sitemap.xml` — 収録URLが1行1URLで返る。404なら `/sitemap_index.xml` も試す(子sitemapのURL一覧が返るので、その中から該当しそうなものをfetchする)
- 一覧から 会社概要・IR・お問い合わせ に当たるURLを選んで fetch する(パスの推測試行による404の無駄打ちを避けられる — fetch計数の節約)
- sitemap も通常のfetchと同じく計数・robots.txt・間隔の対象。URL一覧が長いときは、辿りたいページのURLだけ拾って読み切らない(2000件を超える一覧は先頭2000件のみ返る)

## 4. changes の組み立て

**組み立ての前に必ず [references/fields.md](references/fields.md) を読む** — 8フィールド+条件付きの資本金、それぞれの抽出規則・整形規則・status判断の定義。初回や判断に迷うときは [references/example.md](references/example.md)(実例: 取材テキスト→提出物)も読む。提出物のJSON形状は [schema/submission.schema.json](schema/submission.schema.json)。

要点(詳細は fields.md):

| status | 意味 | 使うとき |
|---|---|---|
| `present` | 値あり | 出典ページで値を確認できた(value に転記) |
| `absent` | 調査したが存在しない | 載りそうな場所(会社概要・お問い合わせ・フッター等)を確認したがどこにもない |
| `unknown` | 調査済み・不明 | 確認したが値を確定できない(複数候補・画像化で読めない・矛盾) |
| `unresearched` | 未調査 | **提出物では使わない**(調査済みなのに未調査は矛盾) |

- **リスト型フィールド(`industries` / `keywords` / `features`)は `present` + 配列でのみ提案**する(空配列・非presentは使わない)
- **資本金(`basics.capital_jpy`)は `supplemental_fields` にあるときだけ提案する**(円単位の整数に換算。「5,000万円」→ `50000000`。会社概要に資本金の記載がなければ `unknown` — 株式会社に資本金は必ず存在するため `absent` にしない。詳細は fields.md)
- `industries` を提案するときは、まず `${CORPDEX_API_URL}/industries` を `corpdex fetch` して語彙IDを確認する(語彙外のIDは機械検証で拒否される)
- **触れたフィールドだけを提出してよい**(部分提出)。1つも確認できないフィールドは changes に入れない
- 提出ファイルは `changes` 配列だけあればよい(`company_id` / `type` / `schema_version` はCLIが注入する)

## 5. 提出

```
corpdex submit <提出物.json>
```

- **422** は機械検証エラー。issues を読んで提出ファイルを直して再提出(サーバーには届いていない)
- **409 schema_version_mismatch** は CLI が旧スキーマ。ユーザーに更新を依頼して終了
- 成功したらタスク完了。続けてよいかユーザーの指示に従う(次は再び claim から)

## 6. 中断・失敗

- 何らかの理由でタスクを完了できないとき(サイト消失・時間切れ・ユーザーの中止指示)は `corpdex task abort --reason <code>` でリースを放棄する(放置すると他の協力者が24時間待たされる)。理由コードは必須で、実態に最も近いものを1つ選ぶ: `fetch_denied`(fetchが403等で拒否)/ `unreachable`(タイムアウト・DNS等で到達不能)/ `site_unidentifiable`(公式サイト候補を特定できない)/ `other`(上記以外)
- fetchがrobots.txt拒否・タイムアウトで続くときは、そのページの情報は諦めて unknown ではなく**提案しない**(出典なき提案はできない)。すべての取材が不能なら abort
- abortした企業は全協力者共通でしばらくタスクに現れなくなる(初回7日・連続で倍増 — ADR 0029)。一時的な障害の可能性が高いとき(ネットワーク断・タイムアウト1回など)は、即 abort せず時間をおいて再試行してから判断する

## 環境非依存の確認

操作はすべて `corpdex` CLI・環境のWebSearch・ファイル読み書きのみ。Claude Code / OpenAI Codex の両方で同じ手順で動く(動作保証はこの2環境)。
